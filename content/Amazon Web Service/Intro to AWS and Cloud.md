# What is the Cloud?
- Before cloud (on-premises servers and data centers)
- With cloud (serverless, pay-as-you-go framework)
- What is AWS? (Amazon Web Services)
- Availability zones and edge locations vs on-premises

## Why should you learn cloud computing
- Industry need for cloud technologies
- Enhanced understanding of software solutions and AI
- Certifications and cloud knowledge give an edge for recruiting

---
## Infrastructure as a Service (IaaS)
- The cloud provider brings the core hardware (servers, storage, networking, etc.)
- Only pay for what you use and avoid infrastructure installation costs
- Easy scalability
- You're still in control but don't need to maintain the physical servers

## Platform as a Service (PaaS)
- Infrastructure is fully handled by the cloud provider
- The user's main job is writing code using the tools provided by the specific cloud services

## Software as a Service (SaaS)
- Cloud-hosted applications delivered to users
- Infrastructure and code are both fully managed, giving users an end product to work with
- Maintain

---
# IAM(Identity and Access Management)
- Authorization is needed to perform tasks and use services in AWS
- Root user vs other users
- Principle of least privilege (give a user the needed privileges, no more, no less)

## IAM Fundamentals
- Identity based: attach directly to a user or a group, to give one the ability to make an EC2 instance (limited access / privileges)
- Resource Policy: Attach this directly to a resource such as S3 bucket itself
## Why IAM
- Used in real organizations to give roles to employees
- Allows you to understand what your using, and stay organized (Things get messy!)

# Amazon EC2 ()
- In the past, companies needed on-premises hardware
- EC2 allows companies to rent virtual computers

# Amazon S3 (Storage)
- Storage similar to Google Drive
- Backbone for table structures, data pipelines, Bedrock models, and more
- Certifications and cloud knowledge give an edge for recruiting

## AWS Lambda
- Way to run code in a serverless way (without needing computers or servers)
- Runs based on triggers and orchestrates interactions between services
- Only pay for when the function is being run
