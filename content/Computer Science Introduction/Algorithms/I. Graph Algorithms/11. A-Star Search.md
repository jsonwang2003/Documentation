> [!abstract] Abstract
> The most widely known form of best-first search is called A* search. It evaluates nodes by combining g(n), the cost to reach the node, and h(n), the cost to get from the node to the goal.

---
## Problem Formulation

> [!info] Definition: 
> **Input:** Directed graph with edge costs and heuristic function, source node, goal node.
> **Output:** The cheapest path solution from start to goal.
> **Paradigm:** Best-first search, priority-queue-driven frontier expansion.
> **Typical use cases:** finding the cheapest solution path when an admissible heuristic is available.

### Core Logic:
Since $g(n)$ gives the path cost from the start node to node $n$, and $h(n)$ is the estimated cost of the cheapest path from n to the goal, we have $f(n) =$ estimated cost of the cheapest solution through $n$. If we are trying to find the cheapest solution, a reasonable thing to try first is the node with the lowest value of $g(n) + h(n)$. The algorithm is identical to [[7. Dijkstra's Algorithm|Dijkstra's Algorithm]] except that A* uses $g + h$ instead of $g$.

---
## Pseudocode

```pseudo
\begin{algorithm}
\caption{A* Search}
\begin{algorithmic}
\Procedure{A*}{startNode, goalNode}
    \State $node$ = a node with STATE = problem.INITIAL-STATE, $G+H$
    \State $frontier$ = a priority queue ordered by $G+H$, with $node$ as the only element
    \State $explored$ = an empty set
    \While{\True}
        \If{$frontier$ is empty}
            \Return failure
        \EndIf
        \State $node$ = pop($frontier$)
        \Comment{chooses the lowest-cost node in $frontier$}
        \If{$problem$.GOAL-TEST($node$.STATE)}
            \Return SOLUTION($node$)
        \EndIf
        \State add $node$.STATE to $explored$
        \ForAll{$action$ in $problem$.ACTIONS(node.STATE)}
            \State $child$ = CHILD-NODE($problem, node, action$)
            \If{$child$.STATE is not in $explored$ or $frontier$}
                \State $frontier$ = insert($child.frontier$)
            \Elif{$child$.STATE is in $frontier$ with higher $g+h$}
                \State replace that $frontier$ node with $child$
            \EndIf
        \EndFor
    \EndWhile
\EndProcedure
\end{algorithmic}
\end{algorithm}
```

## Complexity Analysis

- **Time Complexity:** $\mathcal{O}(...)$ — *Derivation:* Depends on the quality of the heuristic function, reducing the exponential search space of Dijkstra's down to a directed exploration.
- **Space Complexity:** $\mathcal{O}(...)$ — *Derivation:* Requires storing the frontier priority queue and the explored set.

> [!example] Common Issues:
> - Provided that the heuristic function $h(n)$ satisfies certain conditions, search is both complete and optimal.

---
## Correctness

**Condition 1: Admissibility:** An admissible heuristic is one that never overestimates the cost to reach the goal. Because $g(n)$ is the actual cost, $f(n)$ never overestimates the true cost of a solution along the current path though $n$.

**Condition 2: Consistency:** A heuristic is consistent if the estimated cost of reaching the goal from $n$ is no greater than the step cost of getting to $n'$ plus the estimated cost of reaching the goal from $n'$: $h(n) \leq c(n, a, n') + h(n')$. This is a form of the general triangle inequality.

**Optimality of A*:** If $h(n)$ is consistent, then the values of $f(n)$ along any path are nondecreasing. Suppose $n'$ is a successor of $n$; then $g(n') = g(n) + c(n,a,n')$ for some action $a$. Therefore $f(n') = g(n') + h(n') = g(n) + c(n,a,n') + h(n')$. By consistency, $f(n') \geq g(n) + h(n) = f(n)$.
